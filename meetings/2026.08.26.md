## 2. RAG Pipeline

RAG 整体划分为两个 Pipeline：

### 2.1 Ingestion Pipeline

主要负责知识数据的预处理、切分和向量化。

```text
Document
   ↓
Preprocessor
   ↓
Chunker
   ↓
Embedder
   ↓
Database
```

主要组件：

* Preprocessor
* Chunker
* Embedder

---

### 2.2 Inference Pipeline

主要负责用户查询时的检索、排序和 Prompt 构建。

```text
Query
  ↓
Embedder
  ↓
Retriever
  ↓
Reranker
  ↓
Prompt Creator
  ↓
LLM
```

主要组件：

* Embedder
* Retriever
* Reranker
* Prompt Creator

---

## 4. Preprocessor

主要负责原始数据进入 Chunker 前的预处理。

当前考虑：

* 关键词提取

  * 待确定使用模型还是传统算法
* 噪声过滤
* 文本清洗和标准化

---

## 5. Chunker

Chunker 根据不同文档类型采用不同处理策略。

### 5.1 有结构的文本

例如：

* HTML
* XML
* Markdown

处理方式：

* 基于文档结构进行解析
* 按标题、段落、节点等进行切分

---

### 5.2 无结构纯文本

候选方案：

* 固定长度切分
* 基于语义相似度进行切分
* 使用模型进行语义分段

具体方案后续测试决定。

---

### 5.3 复杂文档

例如：

* PDF
* 图片
* 表格型文档

考虑使用 Document Understanding 模型或框架，例如：

* Docling
* PaddleOCR-VL

用于：

* 文档结构识别
* OCR
* 表格解析
* Layout 分析

---

### 5.4 Excel / CSV

使用 Parser 直接解析结构化数据。

---

## 7. Retriever

计划采用 Hybrid Retrieval。

主要组成：

```text
Retriever
├── Vector Retrieval
├── BM25
└── Metadata Filter
```

### Vector Retrieval

基于 Embedding Vector 进行语义检索。

### BM25

用于关键词和文本匹配。

### Metadata Filter

考虑在检索阶段增加 Metadata Filter，例如：

* document type
* source
* category
* language
* version
* time

具体使用方式后续确定。

---

## 8. Reranker

候选模型：

* `bge-reranker-v2-m3`

Reranker 后增加结果过滤逻辑：

* Minimum Score
* Score Gap

例如：

```text
Retrieval Results
       ↓
    Reranker
       ↓
Minimum Score Filter
       ↓
Score Gap Check
       ↓
Final Context
```

用于降低低质量检索结果进入最终 Context 的概率。

---

## 9. Prompt Creator

主要负责构建最终发送给 LLM 的 Prompt。

需要考虑：

* Role / System Prompt
* User Question
* Retrieved Sources
* Context
* Context Length / Token Limit

基本结构：

```text
Role
+
Question
+
Retrieved Context / Sources
=
Final Prompt
```
