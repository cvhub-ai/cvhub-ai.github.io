# 项目

- 构建一个基于计算机视觉的AI Agent
- 每种视觉功能做成一个独立的 CV-Tool
- Agent可以分析问题，构建解决方案，调用CV-Tools，整和最终结果
- 项目部署基于docker
    - 每个 CV-Tool 做成一个独立的
        - git仓库
        - docker镜像
        - gRPC服务
    - Agent也做成一个docker镜像，未来考虑把Agent拆成多个docker镜像，目前先构建一个完整的Agent镜像

# 技术框架

- AI Agent → Python构建
- CV-Tools → 微服务系统，Tool之间通信使用gRPC，每个Tool的框架和编程语言可能不同
- Docker + K8s（未来可能会用）

# CV-Tool 文件结构

下面是一个参考模板，具体情况可以根据需求修改

- models 文件夹 → Tool需要的模型
- src 文件夹 → 模块代码
    - 业务名称文件夹（如 ocr，object detection）→ 核心逻辑代码
        - Pipeline流程
        - 业务引擎构建
        - 模型
    - utils 文件夹 → CV-Tool中的通用方法 大部分情况考虑数学方法 做成静态类
    - config 文件夹 → 配置文件
    - dto 文件夹 → Pipeline流程中用于管理数据的数据结构
    - image processor 文件夹 → 图像处理
- docker file
- library配置

# CV-Tool接口开放规则

尽可能简单，完整，独立，不要把整个服务拆成多个接口，只给出完整Pipeline结果的接口

1. 核心业务接口（单张图片处理接口），整个完整Pipeline的输出结果
2. 批量处理接口
3. Health Check
4. GetCapabilities → 返回当前运行服务的结构化能力和限制，但是不负责返回大段 Tool 使用说
5. GetServiceInfo：可选
