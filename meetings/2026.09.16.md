# CvHub RAG Meeting Summary

## 当前进度

目前主要推进 **RAG Pipeline** 的设计与实现。

## 主要问题与调整

### Inference Pipeline 解耦

* `Preprocess` 与 `Retriever` 耦合度较高，需要进一步解耦。
* `Retriever` 设计统一父类，不同检索方法分别实现具体子类，例如：

  * `VectorRetriever`
  * `BM25Retriever`
* 不同 Retriever 对文本的特定处理应封装在各自类内部，不放在统一的 `Preprocess` 中。
* Pipeline 各模块需要定义标准化的输入/输出接口，方便后续独立替换具体实现。

### Retrieval Result Integration

Inference Pipeline 可能同时使用多个 Retriever，因此需要设计独立的结果整合模块：

```text
VectorRetriever ─┐
                 ├─→ Fusion → Reranker
BM25Retriever ───┘
```

后续需要确定不同 Retrieval Result 的统一格式以及 Fusion 方法。
